## Source once, verify once, reuse many

Resolve the required fact locally before opening an external source. Reuse an unchanged reviewed canonical fact by ID when provenance and relevant audits remain valid. Reopen source review only for changed/missing provenance, uncovered semantics or a detected conflict. Automated source integrity checks still run; they are not an instruction to redo the manual gameplay review for every Character.

Use the existing pinned snapshot/import/review workflow. `sync-character-mechanics.mjs` already fetches one Characters snapshot per invocation or accepts a local snapshot; do not add a fetch-per-Character loop. If broader extraction is justified later, capture enough evidence once to avoid repeated fetches, but reconcile and manually promote bounded fact families. Preserve exact version/commit/blob/path and field evidence. A refresh that changes nothing does not create new gameplay review work.

Keep the direction: external/raw evidence → provider extraction → normalized family evidence → conflicts/reconciliation → manual review → owning canonical facts → shared effects → profiles → execution/combat → DPS → product. Provider observations, canonical fact availability, an isolated primitive, an executable profile and total-team DPS remain separate claims.
