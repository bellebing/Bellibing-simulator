## Safe archival rule

1. Classify **HISTORICAL PRIORITY**, **SUPERSEDED UX IDEA**, **CURRENT SAFETY CONTRACT**, **SOURCE EVIDENCE**, or **LIVE STATUS** per section, not just file title.
2. "Archive" a historical roadmap by **prominently deactivating its order/authority and linking to the current roadmap**. Do not destroy the original, change protected source pins or break inbound relative links merely to organize files.
3. Any **physical move/delete** requires a backlink/reference audit, proof it is not an executable test/source-contract dependency, and an isolated change reviewed under the existing destructive-action/owner-GO rule. This planning Draft deliberately performs **no deletions/renames**.
4. On acceptance, all new Codex prompts use the current project-wide roadmap for destination and process v2 for execution. Feature/task documents only specify local contracts, never compete for global order.
5. At implementation milestones update only current status/affected contract, and record changed bug state only after verified behavior.
