# Improve Settings — public desktop contract

**Improve Settings → Resources → resource controls → separator → accepted settings controls** is the visual hierarchy. Resources is a centered secondary heading. Expanded controls group **Echoes | Tuners | Tubes**, with local Premium Tuner art and four actual Sealed Tube icons (Gold / Purple / Blue / Green) above directly typeable counts. Expanded Tube color captions are hidden visually; exact canonical English item names remain in accessible input names and tooltips. Collapsed summaries visibly retain Gold / Purple / Blue / Green, icons and values, identifying denominations without relying on color alone. Echoes remains text-only because no source-valid neutral item icon was identified. Collapsed settings show a compact line of the same item art and six current values, hide inputs, and retain the accepted settings summaries. Narrow layouts wrap the families and, where needed, Tube denominations without overflow. Enter a whole non-negative count or `∞` / `unlimited`; finite zero remains distinct from unlimited.

Item provenance, pinned identities, byte hashes and the limited fan-companion reuse basis are recorded in [resource-icons/manifest.json](ui-prototypes/assets/resource-icons/manifest.json) and [Asset Source Inventory](ASSET_SOURCE_INVENTORY.md#resource-inventory-item-icons). The build audits the five selective, byte-identical local PNGs and includes them in the explicit public asset boundary.

Resource Inventory is shared user-owned budget context in the existing Improve v3 storage envelope, outside Character records. Old envelopes without inventory start with explicit finite-zero inputs. Corrupt/unsupported saved inventory blocks overwrite and retains recovery bytes; storage write failure cannot commit a changed budget. Character changes, Current/Simulate, exit and simulator reset preserve it. Current and Simulate edit the same inventory and Character-owned Improve Settings through the existing canonical persistence. Settings allow expansion/collapse, direct counts/∞ and all currently supported edits. The Current/Simulate navigation controls are absent; equipment ownership and the underlying sandbox model remain unchanged. No Simulate-only settings copy exists. It is independent of CharacterBuildState, policy and memory-only simulator sessions. No account writeback or spending engine exists.

All visible text and numbers inside Improve Settings, including native inputs/buttons, use the existing `--font-display` Etna source. No unrelated typography or font assets change. Improve Settings and Resources are centered in their owning areas; setting columns use consistent, larger centered titles, separated from their summaries. The inner Character Stats heading remains left-aligned; Flex Stats has only its main column heading. Character Stats is the Target expansion heading in both modes, without repeating Recommended.

UI wording **Hard Requirements** maps to the existing `echoRequirements` / Every Echo per-Echo semantics. Flex Stats with an explicit count use the existing requirement group: all Hard Requirements AND at least N distinct selected Flex Stats, each meeting its own minimum. Legacy preferences without a count remain preferences. Build Need's visible Pending block is removed; its domain support boundary is unchanged.

Collapsed Settings columns are **Sonata Sets / Gate / Required Substats / Flex Substats / Stats**, below Resources. A single responsive grid divides all width left after the four existing gaps and a 64px Gate equally between Sonata Sets, Required Substats, Flex Substats and Stats. Sonata Sets has one empty presentation-only field using the existing Settings field styling, with no selection control or displayed selection. Stats retains the existing Target control, Required Substats retains Hard Requirements and Flex Substats retains Flex Stats. Column widths accommodate this desktop arrangement without horizontal overflow; colors, fonts, borders and controls retain the existing styling.

The shared expanded layout remains **Target / Gate / Hard Requirements / Flex Stats** without the global Recommended / Customize controls or their layout container. Target and Gate retain their narrow widths; Hard Requirements and Flex Stats retain their equal widths. Gate choices remain +5/+10/+15/+20/+25. These are user inputs, not executable decision policy.

Stats displays the source-backed defaults until explicitly edited through its existing Add stat/editor controls. Opening an editor does not seed or persist an override. Supported Echo sliders are directly editable; explicit edits use the existing stored mode transitions. The existing Use Recommended and Reset to Recommended actions retain their normal section behavior. For a stale source/context binding or rejected legacy Echo record only, the existing Reset to Recommended action performs the full Character policy reset, preserving Gate, roll quality, Resources, equipment and unrelated Characters. It remains accessible through Flex expansion when legacy settings are rejected; failed recovery writes retain the original bytes. No replacement mode or navigation controls are introduced.

Recommended Target displays only an unambiguous source-backed modern DEFAULT Calc reference. Source families never fill gaps in one another. Missing references display Pending.

The presentation uses main's shared four-column expansion and compact single-row stat styling. Each of the 13 canonical Echo substats appears exactly once across Hard Requirements, Flex Stats and the existing collapsible Show other stats. The original three-line handle and native drag interaction move every row, including inactive rows, between these sections or within their order. Focusable handles support Alt + Left/Right between sections and Alt + Up/Down within a section, retaining focus after moves. A move from Recommended creates explicit Customize intent for its destination.

One compact count slider precedes the existing Flex rows, without a new heading or any change to the existing drop zones. It displays `At least N of M`, where M is the selected pool. Its valid range is 1 through min(M, 5 − number of Hard Requirements). Count-less legacy settings display an unconfigured state rather than silently adding a requirement; the zero slider position is only this unconfigured sentinel. Empty pools display an explicit empty state with the control disabled. Dragging preserves the exact count; if the pool or Hard count makes it infeasible, a visible validation message and aria-invalid state require the user to repair it. No count is silently clamped in saved intent.

Active Hard Requirements and Flex Stats keep the original compact inline minimum-roll sliders. Show other stats has rows and handles only. Moving any stat into Hard Requirements or Flex Stats immediately activates it and displays its inline minimum-roll slider and exact value. Moving it to Show other stats immediately deactivates it and remembers the minimum for future reactivation. Section membership reflects effective activation; stat labels do not toggle selection. Previously inactive saved placements project into Show other stats without adding acceptance criteria or changing saved minimums. Row placements and dormant minimums are user-owned presentation data in the same v3 Character record; they are not acceptance criteria. Existing valid v3 requirements/preferences, minimums, explicit empty sections and order remain intact. Rejected card settings retain their original bytes and block edits until the existing Reset to Recommended action explicitly resets that Character’s policy; Gate, roll quality and shared Resources survive this reset. They are never mapped to legacy Flex or executed as hidden acceptance requirements.

Gold marks Character-recommended relevance independently of active selection or section placement. For Augusta/default, the user-approved UI guidance is CRIT Rate, CRIT DMG, Energy Regen, ATK% and Heavy Attack DMG; the other eight rows remain neutral and draggable. This limited UI highlight set establishes neither roster-wide reviewed recommendation coverage nor evaluator mechanics. Public recommended Echo requirements/preferences remain Pending; no selection or minimum is inferred from highlighting. Other Characters keep existing source-backed relevance presentation.

For fresh Augusta/default Echo settings, Recommended applies the user-approved configuration: Hard Requirements contains CRIT Rate and CRIT DMG; Flex Stats contains ATK%, Heavy Attack DMG, Energy Regen and neutral Flat ATK, in that order. The other seven stats start in Show other stats. Each active stat uses its lowest existing canonical roll tier. The explicit selected-flex requirement group defaults to at least 1 of the four Flex Stats. This is USER_DEFINED intent, separate from Pending provider recommendations, and proves neither gameplay policy nor evaluator readiness. Existing Echo overrides, explicit empty sections, saved layout and deferred migration take precedence. The first slider edit or move preserves the full default before customizing it; Reset to Recommended restores the applicable default. Other Characters receive no added requirements.

Settings remain Character-isolated. Context/source drift suspends incompatible saved intent; reset is explicit. Storage failures retain recovery data. Existing v2 data is not overwritten, and source recovery does not invent or retarget user choices. Legacy settings containing retired fields require review instead of being executed.
