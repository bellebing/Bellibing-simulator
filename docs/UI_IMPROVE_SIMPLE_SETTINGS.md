# Improve Settings — public desktop contract

**Improve Settings → Resources → resource controls → separator → accepted settings controls** is the visual hierarchy. Resources is a centered secondary heading. Expanded controls group **Echoes | Tuners | Tubes**, with local Premium Tuner art and four actual Sealed Tube icons (Gold / Purple / Blue / Green) above directly typeable counts. Expanded Tube color captions are hidden visually; exact canonical English item names remain in accessible input names and tooltips. Collapsed summaries visibly retain Gold / Purple / Blue / Green, icons and values, identifying denominations without relying on color alone. Echoes remains text-only because no source-valid neutral item icon was identified. Collapsed settings show a compact line of the same item art and six current values, hide inputs, and retain the accepted settings summaries. Narrow layouts wrap the families and, where needed, Tube denominations without overflow. Enter a whole non-negative count or `∞` / `unlimited`; finite zero remains distinct from unlimited.

Item provenance, pinned identities, byte hashes and the limited fan-companion reuse basis are recorded in [resource-icons/manifest.json](ui-prototypes/assets/resource-icons/manifest.json) and [Asset Source Inventory](ASSET_SOURCE_INVENTORY.md#resource-inventory-item-icons). The build audits the five selective, byte-identical local PNGs and includes them in the explicit public asset boundary.

Resource Inventory is shared user-owned budget context in the existing Improve v3 storage envelope, outside Character records. Old envelopes without inventory start with explicit finite-zero inputs. Corrupt/unsupported saved inventory blocks overwrite and retains recovery bytes; storage write failure cannot commit a changed budget. Character changes, Current/Simulate, exit and simulator reset preserve it. Current and Simulate edit the same inventory and Character-owned Improve Settings through the existing canonical persistence. Both allow expansion/collapse, direct counts/∞ and all currently supported settings edits. No Simulate-only settings copy exists. It is independent of CharacterBuildState, policy and memory-only simulator sessions. No account writeback or spending engine exists.

All visible text and numbers inside Improve Settings, including native inputs/buttons, use the existing `--font-display` Etna source. No unrelated typography or font assets change. Improve Settings and Resources are centered in their owning areas; Target, Gate, Hard Requirements and Flex Stats are consistent, larger centered column titles, separated from their summaries. Inner Character Stats and Flex Stats headings remain naturally left-aligned. Character Stats is the Target expansion heading in both modes, without repeating Recommended.

UI wording **Hard Requirements** maps to the existing `echoRequirements` / Every Echo per-Echo semantics. Flex Stats remain preferences, not an implicit at-least-one rule. Build Need's visible Pending block is removed; its domain support boundary is unchanged.

The visible settings controls are Target / Gate / Hard Requirements / Flex Stats with one Recommended / Customize mode. Target and Gate are narrower than main's original widths; Hard Requirements and Flex Stats share equal widths. Gate choices remain +5/+10/+15/+20/+25. These are user inputs, not executable decision policy.

Recommended Target displays only an unambiguous source-backed modern DEFAULT Calc reference. Source families never fill gaps in one another. Missing references display Pending.

The presentation uses main's shared four-column expansion and compact single-row stat styling. Each of the 13 canonical Echo substats appears exactly once across Hard Requirements, Flex Stats and the existing collapsible Show other stats. The original three-line handle and native drag interaction move every row, including inactive rows, between these sections or within their order. Focusable handles support Alt + Left/Right between sections and Alt + Up/Down within a section, retaining focus after moves. A move from Recommended creates an explicit Customize layout without selecting an inactive stat.

Active Hard Requirements and Flex Stats keep the original compact inline minimum-roll sliders. Show other stats has rows and handles only. Moving an active stat between Hard Requirements and Flex Stats transfers its existing selection and minimum; moving it to Show other stats explicitly deactivates it and remembers the minimum. Moving an inactive stat does not select it. Reactivation restores its configured value. Row placements and dormant minimums are user-owned presentation data in the same v3 Character record; they are not acceptance criteria. Existing valid v3 requirements/preferences, minimums, explicit empty sections and order remain intact. Rejected card settings retain their original bytes and block edits until the existing Recommended action explicitly resets that Character’s policy; Gate, roll quality and shared Resources survive this reset. They are never mapped to legacy Flex or executed as hidden acceptance requirements.

Gold marks Character-recommended relevance independently of active selection or section placement. For Augusta/default, the user-approved UI guidance is CRIT Rate, CRIT DMG, Energy Regen, ATK% and Heavy Attack DMG; the other eight rows remain neutral and draggable. This limited UI highlight set establishes neither roster-wide reviewed recommendation coverage nor evaluator mechanics. Public recommended Echo requirements/preferences remain Pending; no selection or minimum is inferred from highlighting. Other Characters keep existing source-backed relevance presentation.

Settings remain Character-isolated. Context/source drift suspends incompatible saved intent; reset is explicit. Storage failures retain recovery data. Existing v2 data is not overwritten, and source recovery does not invent or retarget user choices. Legacy settings containing retired fields require review instead of being executed.

The detached browser getState API returns user inputs, public presentation and compatibility status only. It does not expose internal decision policy or mutate build/equipment.

Improvement Cost / evaluator uses a private decision-engine contract. Proprietary policy and calibration are not part of the public repository.
