# Improve Settings — public desktop contract

**Improve Settings → Resources → resource controls → separator → accepted settings controls** is the visual hierarchy. Resources is a centered secondary heading. Expanded controls group **Echoes | Tuners | Tubes**, with local Premium Tuner art and four actual Sealed Tube icons (Gold / Purple / Blue / Green) above directly typeable counts. Expanded Tube color captions are hidden visually; exact canonical English item names remain in accessible input names and tooltips. Collapsed summaries visibly retain Gold / Purple / Blue / Green, icons and values, identifying denominations without relying on color alone. Echoes remains text-only because no source-valid neutral item icon was identified. Collapsed settings show a compact line of the same item art and six current values, hide inputs, and retain the accepted settings summaries. Narrow layouts wrap the families and, where needed, Tube denominations without overflow. Enter a whole non-negative count or `∞` / `unlimited`; finite zero remains distinct from unlimited.

Item provenance, pinned identities, byte hashes and the limited fan-companion reuse basis are recorded in [resource-icons/manifest.json](ui-prototypes/assets/resource-icons/manifest.json) and [Asset Source Inventory](ASSET_SOURCE_INVENTORY.md#resource-inventory-item-icons). The build audits the five selective, byte-identical local PNGs and includes them in the explicit public asset boundary.

Resource Inventory is shared user-owned budget context in the existing Improve v3 storage envelope, outside Character records. Old envelopes without inventory start with explicit finite-zero inputs. Corrupt/unsupported saved inventory blocks overwrite and retains recovery bytes; storage write failure cannot commit a changed budget. Character changes, Current/Simulate, exit and simulator reset preserve it. Current and Simulate edit the same inventory and Character-owned Improve Settings through the existing canonical persistence. Both allow expansion/collapse, direct counts/∞ and all currently supported settings edits. No Simulate-only settings copy exists. It is independent of CharacterBuildState, policy and memory-only simulator sessions. No account writeback or spending engine exists.

All visible text and numbers inside Improve Settings, including native inputs/buttons/selects, use the existing `--font-display` Etna source. Resources remains above a five-column settings area: **Target / Gate / Hard Requirements / Any Of / Not Important**. Target and Gate are narrower; all three stat-category columns have equal widths. Existing Target editors and Gate +5/+10/+15/+20/+25 choices remain user inputs, without decision-engine execution.

There is one canonical collection of thirteen Echo substat cards. Every stat occurs in exactly one category. Each card always shows its name, an editable discrete canonical minimum-roll slider and the exact selected ratio/point value. Grey Not Important cards remain editable. A native category selector supports pointer and keyboard movement and preserves the minimum; card color indicates membership only.

**Hard Requirements** requires all selected stats on each final target-qualified Echo, each meeting its minimum. **Any Of** selects alternatives and owns an explicit `anyOfMinimumCount`: at least that many distinct selected stats must meet their minimums. Count edits are limited by both the selected pool and five minus Hard Requirements. Pool/category changes preserve the saved count. Impossible configurations display validation and project a Pending requirement without erasing intent. With an empty pool, the neutral count is 1; a retained larger count requires explicit correction or enough new alternatives. **Not Important** excludes stats from this configured requirement; it does not declare them universally useless. Build Need remains a separate whole-Character Pending concept.

`overrides.echoCards` lives in the existing Improve v3 Character-owned envelope and is the authoritative unified input collection. It stores category/minimum per canonical stat and the Any Of count; valid public requirements are derived from it, with `groups[].minimumCount` exposed as user input. No parallel settings store or acceptance evaluator exists. Legacy Echo requirements/preferences and v2 intent remain retained and require explicit review/reset before using the new categories; old Flex relevance is never silently promoted to an at-least-one requirement. Invalid saved card identities, tiers or context are suspended and retain recovery intent.

One global **Recommended / Customize** mode remains. Editing any card transitions to Customize, retaining all current card values and Target inputs. Reset to Recommended explicitly clears manual overrides and restores only compatible, verified source-backed requirements with exact canonical minimums and explicit group counts. Missing reviewed Echo recommendations remain visibly unsupported: neutral Not Important cards offer lowest canonical tiers as prospective manual inputs, without creating a Recommended preset or selected requirement. Verified relevance/preferences alone do not imply Any Of membership. Manual requirements can be configured for a fresh Character even when reviewed source context is unavailable; previously source-bound saved intent remains suspended until matching source/context returns or the user resets it. Recommended Character Target still displays only an unambiguous modern DEFAULT Calc reference, with no cross-family fallback.

Settings remain Character-isolated. Context/source drift suspends incompatible saved intent; reset is explicit. Storage failures retain recovery data. Existing v2 data is not overwritten, and source recovery does not invent or retarget user choices. Legacy settings containing retired fields require review instead of being executed.

The detached browser getState API returns user inputs, public presentation and compatibility status only. It does not expose internal decision policy or mutate build/equipment.

Improvement Cost / evaluator uses a private decision-engine contract. Proprietary policy and calibration are not part of the public repository.
