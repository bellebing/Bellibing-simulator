## Owner focus clarified — 2026-10-25: **manual Echo entry first**

**Primary problem:** players must currently enter their owned Echoes manually. The job of this bank is therefore to **study concrete interaction patterns in other working tools and explain what Bellibing should borrow/improve**. Scanner/OCR remains future relief, **not a dependency** for a fast, correct manual editor. Research priority: **actual Echo entry → correction → next Echo → repeat across five owned slots**. UI polish, advanced scoring, broad game-version history and scanner architecture are secondary. Keep every cited behavior's evidence level explicit.

**End-to-end design hypothesis, NOT implemented/tested:** select an owned Character or one of five Echo slots → show the existing contextual Echo identity (no redundant character selection) → choose Echo, Cost/Sonata/Main Stat using only legal options → immediately display +5 → **choose stat (1) + exact tier value (2)** → stage closes and +10 opens; repeat through available checkpoints → finish the item with one explicit Save/Add as Owned and an obvious “Next Echo” target. **Five revealed substats = 10 taps in the roll-entry portion, not 10 taps for the entire item.** Do not auto-invent ownership, save from a recommendation, or commit an Import/Candidate to Current. A partly tuned +5/+10 piece must be equally easy to enter and reopen.

**UX priorities for a future real 1440×900 desktop comparison:** broad visible stat buttons; exact source-backed **discrete values** beside selected stat; mark chosen stats unavailable, never silently delete later rolls; full keyboard navigation and Escape/Undo; no dropdown/popover/extra confirmation at each roll; single visible Echo summary and current +5 step; reuse actual previously entered physical items instead of retyping; default *presentation context* to the active slot/Character without defaulting unobserved gameplay facts. Avoid sliders for substat value entry unless a discrete, labeled slider **beats** direct value buttons in an actual test.

**Benchmark to run once M1 concept starts (research targets, not achieved claims):** real player transcribes a source-valid +25 Echo (five stats) and a partial +10 Echo from the game UI; count all pointer/keyboard actions including Echo identity, Main Stat, save and “next”; total seconds, misclicks, corrections, accidental account writes, changes of focus and unnecessary scrolling. Independently audit the **10-click five-roll target** and the full-item time, since the former alone can hide a terrible setup flow.

## Interaction principles to evaluate

- **Minimize decisions and clicks:** prefer broad, visible choices; show the next likely action immediately.
- **Inline over nested popups:** disclose details directly beneath the relevant control without losing the current context. Keep source-backed static/derived fields noneditable.
- **Sliders for constrained, ordered values:** clearly label exact selected values, allow keyboard entry/steps and use discrete ticks only when values are actually discrete; never approximate canonical Echo rolls.
- **Helpful defaults without false ownership:** source-supported recommendations can prefill a *template*, never create owned Echo items or silently replace Current. Missing recommendations remain Pending.
- **Immediate, honest feedback:** preview the effect of a change while preserving Current versus Candidate and the private evaluator/readiness boundary. A live number or score from an external site does not establish Bellibing gameplay parity.
- **Fast import with safe review:** imported/scanned data becomes an editable staged preview with unknowns flagged; only explicit commit writes owned inventory.

### UX synthesis — adopt principles, avoid their friction

1. **Borrow:** Fribbels' *scope-of-import* choice + WutheringTools' **photo next to corrections** + Genshin Optimizer's **start from an owned inventory**. **Improve:** one staged editor shared by import, manual input and later scanner; Current never changes on import alone.
2. **Borrow:** In-game Echo identity, names, Cost/Level/Main/Secondary/Substats/Sonata ordering and recognizable portraits. **Improve:** Bellibing's two-click per-roll inline Workshop, automatic next stage, Undo and no popups. External screenshots **never** supply canonical tier values.
3. **Borrow:** WutheringTools' visible swap delta and per-character context. **Improve:** a stable Current-versus-Candidate comparison; show only source-qualified changes and mark pending/exploratory numbers honestly.
4. **Borrow:** In-game 3.7 *compact visual stacks*. **Improve:** differentiate *unupgraded identical-looking group* from **owned physical instances** and equipped slots; scanner review must not silently fabricate an item for each supposed game object.
5. **Avoid:** UI layouts replicated pixel-for-pixel, copied icons/art/source code, unvalidated OCR autofill, too many tabs/modals/metrics, auto-equipping presets, misleading universal score or percentage, and premature mobile UX work. **Current owner policy is desktop-only** until a new mobile GO.

## Bellibing-specific north star: Issue #352 (do not dilute)

**Echo Workshop quick roll:** choose Main Stat → open **+5** inline; at each +5 / +10 / +15 / +20 / +25 stage, **click 1 = one wide valid unused stat label; click 2 = one exact source-valid roll value for that stat; the completed stage collapses and the next opens automatically.** No `Substat 1` placeholder, nested dropdown, 170px scroll popup or per-roll confirmation. Main Stat and the roll tiers must come from reviewed canonical legality, never these reference sites.

The future **interactive M1 concept**, after M0 priority clears, should show this with **one real source-backed +5 example** and then check editing earlier stages without silently deleting later rolls, partial +5/+10, invalid duplicates, Undo, touch and keyboard focus. Treat “two clicks” as an **acceptance target to test in a real browser**, not an achieved result. Build/Inventory/Scanner must keep a distinct physical Echo identity, explicit equip/save, import review and Current versus Candidate versus Sandbox isolation; never call a screenshot preview “OCR”. Stop for the owner's visual GO before touching production.
