## Interaction principles to evaluate

- **Minimize decisions and clicks:** prefer broad, visible choices; show the next likely action immediately.
- **Inline over nested popups:** disclose details directly beneath the relevant control without losing the current context. Keep source-backed static/derived fields noneditable.
- **Sliders for constrained, ordered values:** clearly label exact selected values, allow keyboard entry/steps and use discrete ticks only when values are actually discrete; never approximate canonical Echo rolls.
- **Helpful defaults without false ownership:** source-supported recommendations can prefill a *template*, never create owned Echo items or silently replace Current. Missing recommendations remain Pending.
- **Immediate, honest feedback:** preview the effect of a change while preserving Current versus Candidate and the private evaluator/readiness boundary. A live number or score from an external site does not establish Bellibing gameplay parity.
- **Fast import with safe review:** imported/scanned data becomes an editable staged preview with unknowns flagged; only explicit commit writes owned inventory.

## Bellibing-specific north star: Issue #352 (do not dilute)

**Echo Workshop quick roll:** choose Main Stat → open **+5** inline; at each +5 / +10 / +15 / +20 / +25 stage, **click 1 = one wide valid unused stat label; click 2 = one exact source-valid roll value for that stat; the completed stage collapses and the next opens automatically.** No `Substat 1` placeholder, nested dropdown, 170px scroll popup or per-roll confirmation. Main Stat and the roll tiers must come from reviewed canonical legality, never these reference sites.

The future **interactive M1 concept**, after M0 priority clears, should show this with **one real source-backed +5 example** and then check editing earlier stages without silently deleting later rolls, partial +5/+10, invalid duplicates, Undo, touch and keyboard focus. Treat “two clicks” as an **acceptance target to test in a real browser**, not an achieved result. Build/Inventory/Scanner must keep a distinct physical Echo identity, explicit equip/save, import review and Current versus Candidate versus Sandbox isolation; never call a screenshot preview “OCR”. Stop for the owner's visual GO before touching production.
