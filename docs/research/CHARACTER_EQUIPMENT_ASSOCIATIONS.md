# Character–Equipment Associations — Worker 14

**Datum:** 2026-10-11. **Scope:** Augusta, Cartethyia och Chisa. Research endast: ingen implementation, ingen canonical fact-promotion, ingen merge. Utgångspunkt är GitHub main 2026-10-11. Research i Draft PR [#255](https://github.com/bellebing/Bellibing-simulator/pull/255), [#256](https://github.com/bellebing/Bellibing-simulator/pull/256) och [#257](https://github.com/bellebing/Bellibing-simulator/pull/257) är **separata, ännu ej integrerade** källor.

## Slutsats

**Tre starka Character–Weapon-associationer** finns: Augusta–Thunderflare Dominion, Cartethyia–Defier's Thorn och Chisa–Kumokiri. Officiella spelutgivartexter stöder tematiska berättelsekopplingar och/eller samordnade Character-/Weapon-Convenes. **Prydwen**, inte de granskade officiella texterna, använder här uttryckligen ordet *Signature*. Den starkare utsagan ”officiellt explicit deklarerat Signature Weapon” är därmed **PENDING**, inte något vi får härleda enbart från release eller guide.

**En explicit Character-restricted equipment-effekt är VERIFIED för fokusgruppen:** Reminiscence: Fleurdelys **extra** +10% Aero DMG i main slot gäller bara **Cartethyia eller Rover (Aero)**. Den allmänna +10%-grenen på samma Echo saknar Character-restriction. Inget granskat vapen eller Sonata-set i fokusgruppen är belagt som Character-locked. Det gäller **granskade effect-rows**; frånvaro i denna rapport bevisar inte frånvaro av varje framtida/ogranskad mekanik.

## Begrepp, verifiering och källversioner

| Relationsklass | Vad den bevisar – inte bevisar |
| --- | --- |
| **MECHANICAL_RESTRICTION** | En namngiven effekt har en källverifierad wielder-/Character-identity-gate. Inte att hela utrustningen är exklusiv eller BiS. |
| **MECHANICAL_SYNERGY** | En source-backed trigger/värde/scope som ett kit eller team kan uppfylla. Inte säker uptime, rotation, Character-exklusivitet eller DPS. |
| **OFFICIAL_ASSOCIATION** | Utgivarens narrativa vapenbeskrivning, eller en tydlig gemensam Character-/Weapon-kampanj. Inte automatiskt explicit Signature-etikett. |
| **GUIDE_RECOMMENDATION** | Ett källspecifikt buildval med mode, team, rank och andra antaganden. Inte ett spelmekaniskt faktum eller global BiS. |
| **CO_RELEASE_ONLY** | Samma patch/releasedatum utan starkare observerad länk. Bevisar inte Signature. |

**VERIFIED** gäller enbart radens snäva påstående (effekt, officiell presentation eller att guiden faktiskt rekommenderar ett objekt). **PENDING** betyder att en starkare association, källa, timing eller jämförbarhet ännu inte har verifierats. **CONFLICT** används när siffer-/teamkontexter skiljer sig eller gamla dokument säger något som senare kanonisk kod rättat; det är inte licens att slå ihop versionerna.

## Begränsning kontra design — exakt slutsats

- **VERIFIED effekt-gate:** Fleurdelys ECHO_60001065_AERO_DMG_ROVER_CARTETHYIA kräver main-slot och wielder **Cartethyia eller Rover (Aero)**. Den generiska ECHO_60001065_AERO_DMG på samma Echo är **separat**.
- **VERIFIED mekanik utan Character-gate:** Crown of Valor (shield); Windward (Aero Erosion på target vid hit); Rejuvenating Glow (heal); Thread of Severed Fate (Havoc Bane); Kumokiri (stacks/Negative Status). Condition på **event eller target** är **inte** detsamma som restriction på Character-ID.
- **PENDING officiellt uttrycklig Signature-certifiering:** starka officiella lore-/promo-länkar finns, men i genomlästa officiella texter saknas entydig direkt etikett ”X är Y:s signature weapon”. Prydwen benämner tre sådana *signature* som tredjepartspåstående. Samma releasedatum ska lagras som CO_RELEASE_ONLY om det är allt källan visar.

## Förslag: befintliga ägare, inga parallella databaser

1. **Raw:** [gameDataDomain.ts](../../src/gameDataDomain.ts) låter Character/Weapon/Echo/Sonata-katalogerna äga identitet, typ, COST, Sonata membership och release. Behåll nuvarande regel att CharacterGameData **inte** äger default/signature/recommended equipment. Ingen påhittad signatureWeaponId från en guideetikett.
2. **Effects:** befintlig [echoEffectDomain.ts](../../src/echoEffectDomain.ts) med wielderCharacterIds + [echoCharacterRestrictedEffects.ts](../../src/data/echoCharacterRestrictedEffects.ts) ska fortsatt vara sanningsägare för mekaniska identity gates. Weapon- och Sonata-effect IDs för trigger/värden/scope ägs av sina effektkataloger, aldrig av associationer. Flera effektgrenar på samma Echo förblir separata.
3. **Profiles/rekommendationer:** [profileDomain.ts](../../src/profileDomain.ts), [weaponRecommendations.ts](../../src/data/weaponRecommendations.ts), [echoLoadoutProfiles.ts](../../src/data/echoLoadoutProfiles.ts) och genererade/approved profilfamiljer behåller relationer med characterId, source, role/mode, rank, team, set och main Echo. defaultWeaponId/label ”Signature / Best in Slot” anger **källvalt referensval**, inte ett nytt mekanik- eller officiellt attribut.
4. **Om separat officiell association behövs i UI:** lägg en *typed evidence claim* som metadata **på befintlig relations-/provenance-ägare**, refererande samma characterId och equipmentId: relationKind, evidenceKind (OFFICIAL_LORE / OFFICIAL_PROMOTION / GUIDE / CO_RELEASE), sourceUrl, gameVersion, reviewedAt, status, contextKey och eventuellt effectId. Inga kopierade effect-värden, ingen global BiS-tabell och ingen extra parallel signature database. Måste source-granskas innan promotion.
5. **Downstream:** håll rekommendation skild från faktisk utrustning, trigger-state och DPS. Vid eventuell promotion krävs [Data Verification Policy](../DATA_VERIFICATION_POLICY.md), source pins, backward-impact och relevanta audittester. Denna PR ändrar **ingen** sådan canonical data.
