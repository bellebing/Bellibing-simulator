# Mornye Minor Forte Healing Bonus — source evidence

**Worker 9 · 2026-10-11 · research-only · base: `main` at `102b66edec165f3d2a313a562de4049a26424924`**

## Decision and disposition

**Source-supported fully unlocked Minor Forte Healing Bonus: +12.00%.** Four **separate permanent stat nodes** contribute `1.80% + 4.20% + 1.80% + 4.20%`. This is supported by extracted **game-version 3.6.0** tree data, an independently checked **3.7.0** release tree, the source-localized English node text, and Game8's individual Forte stat rows. There is **no source-supported +10.00% node combination**.

**Status: research VALUE RESOLVED (+12%); cross-owner catalog discrepancy remains PENDING remediation.** This document alone does not promote a new canonical stat, amend the `VERIFIED` tag, or close the mismatch in runtime/exports. The old intrinsic record currently states +10% and cannot be treated as an independently verified game total while it disagrees with the release tree. No in-client/live-game screenshot was captured; this finding establishes the **game-data/source-backed** value, not an independently observed player's live stat screen.

**Internal control — the separate DEF strands:** rows `698/702` (Normal Skill root `2`) and `699/703` (Resonance Liberation root `3`) supply **2.28% + 5.32% per strand**, yielding **15.20% DEF** fully unlocked. That independently matches the current intrinsic DEF number, so this is not a one-strand-vs-two-strands convention for the Healing discrepancy. Raw DEF properties use `Property.Id:10010` with `IsRatio:true`; they are not Healing properties.

## Why the existing GitHub files diverge

1. [`src/data/characterIntrinsicStats.ts`](../../src/data/characterIntrinsicStats.ts) has `verified('mornye', [Healing Bonus:0.10, DEF%:0.152])`, citing “Prydwen — current Minor Fortes” and “Wutheringlab — current Forte nodes”, with a separate DEF node-level correction and review date **2026-08-31**. That record mixes an **aggregate Healing guide claim** with a **node-corrected DEF total**; its `VERIFIED` label does not override conflicting original node evidence.
2. [`data/source/character-forte-ui.json`](../../data/source/character-forte-ui.json) and [`src/characterForteUi.mjs`](../../src/characterForteUi.mjs) ingest **individual source rows**. The projection checks both original `Property` units and displayed parameter strings, sums only enabled `kind:'stat'` nodes, and consequently produces **+12%** at full investment in the **interactive Build Stats**. It deliberately replaces, rather than additionally counts, the catalog intrinsic contribution in this projection; see [UI source contract](../UI_FORTE_TREE_SOURCE.md).
3. [`test/characterForteUi.test.ts`](../../test/characterForteUi.test.ts) explicitly expects the discrepancy: **tree `{Healing Bonus:0.12, DEF%:0.152}` vs intrinsic `{Healing Bonus:0.1, DEF%:0.152}`**. The previous Forte-source integration retained it as **PENDING** instead of silently overwriting the older owner. **Worker 6 Draft PR #257** independently re-reports that same cross-owner conflict in its [Character Facts coverage](https://github.com/bellebing/Bellibing-simulator/pull/257); PR #257 is **not merged** and is evidence/audit, not another source of new game mechanics.

**Root cause within Bellibing:** two separately sourced owners (derived catalog totals vs original individual stat tree) were never reconciled for Healing. The old `+10%` can be traced to currently published secondary aggregate guides; the exact historical editorial reason it was kept after DEF's per-node review is **not recorded**. No evidence supports labeling this an intentional gameplay conditional, an additive healing buff, or a valid alternative unlock configuration.
