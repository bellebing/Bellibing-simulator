# Sandbox execution — S2A review boundary

S2A connects actual detached S1 owner values to the existing private engine locally. It does not enable browser SIMULATE, HTTP ingress, deployment, accounts or persistence. Production `ACCOUNT_BUILD` is unchanged. Public code adds only neutral observed receipt aggregation and contract tests; no private evaluator/policy or research fixture is bundled.

## Verified integration and independent evidence

The private integration captures the actual Sandbox Character/build, five templates, active mask, selected slot, Settings, resources and owner revisions. Augusta/default uses the existing canonical standard and supported private policy. Real single/five-slot completions, abort, resource blocking and censoring have been executed and replayed. Exact quantities, private implementation revision and reproducible evidence stay in the private repository. Public tests do not claim engine execution.

The public executable dependency is `32d8c348534cd8248e8b99d08221e06efb5bc6b9`; later documentation-only review heads do not change that immutable pin. The original canonical gameplay/Settings source pins remain unchanged and audited. GitHub owns final heads and check status.

Every action, cached retry, response acceptance and export rechecks captured values against the actual live S1 owners. Character round-trips, settings/resources/templates/selection/mode/reset changes retire a run permanently. Existing transport request idempotency prevents double spending; terminal runs reject new work. These local trusted-host checks are not remote authorization or a guest session service.

Unsupported Characters, changed Weapon context and unsupported Gate/minimum/Settings return Pending before spending; no automatic default fallback. Invalid configuration rejects before starting. Manual supported Main Stat/species/Sonata/Hard-Flex/active-slot/budget edits pass through the existing canonical compiler. 59 source-backed templates do not imply 59 supported engine configurations.

## Safe presentation/export

The existing transport V1 presentation supplies numbered slots, Current, New Candidate, completion, exact Trash observations/history, trace events and resource receipts. Retained incomplete Current denotes Temporary. Browser-facing data is read-only: neither actual account owners nor S1 input/history owners are overwritten. The future renderer must use the safe DTO or a reviewed disposition API rather than resurrecting retired cards.

The versioned `BELLIBING_SANDBOX_RUN_EXPORT_V1` envelope allowlists context, existing presentation and observed Simulated Cost. It excludes private replay input, policy, weights, economics, diagnostic scores, calibration and private release mappings. Private replay is verified separately, then projected and compared to the safe envelope; safe JSON is not a private research replay file.

`aggregateSimulatedResources` validates committed event order, exact before/after balance and denomination receipts. It retains gross/returns/net/remaining and actual zero versus missing semantics. `simulatedCostPresentation` prepares the existing compact table shape; no browser wiring is made here. Expected is null, never inferred from an observed run. See [cost contract](SANDBOX_RESOURCE_COST.md).
